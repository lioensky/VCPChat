# VCPdesktop 挂件运行时与远控参考

> 截至 2026-11-01。补充 `README.md` 与 `VCPdesktop介绍文档.md` 未收录的模块与行为。内容以源码为准。

## 一、挂件沙箱内可用的变量

| 变量 | 说明 |
|---|---|
| `document` | 代理对象，`querySelector` / `getElementById` 限定在本挂件内，`body` 指向内容容器 |
| `window` | Proxy，`setInterval` / `setTimeout` / `addEventListener` / `requestAnimationFrame` 登记到本挂件名下，挂件移除或刷新时自动回收 |
| `widgetId` | 本挂件 ID |
| `vcpAPI` | `fetch(endpoint, opts)`、`post(messages, opts)`、`weather()` |
| `musicAPI` | `play` / `pause` / `getState` / `setVolume` / `seek` / `send` |
| `widgetFS` | 挂件私有文件，见第二节 |
| `PIXI` | 包装后的 Pixi v8，`new PIXI.Application()` 的实例随挂件销毁 |
| `_realDoc` / `_realWindow` | 真实的桌面 document 与 window。挂件之间没有安全隔离，只运行可信挂件 |

## 二、widgetFS（挂件私有文件）

```js
await widgetFS.saveFile('state.json', JSON.stringify(data));       // 可选第三参数 'base64'
const r = await widgetFS.loadFile('state.json');                   // { success, content, encoding }
const list = await widgetFS.listFiles();                           // { success, files: [{ name, size, isText }] }
```

- 文件存放在 `AppData/DesktopWidgets/{savedId}/`，挂件必须有 `savedId`。
- 有 `savedId` 的情况：从收藏或预设恢复；经 DESKTOP_PUSH 推送且已归档（见第六节）；CreateWidget 传了 `preSavedId` 或 `autoSave`。
- `widget.html`、`meta.json`、`thumbnail.png` 受保护，不能写。
- 同一 `savedId` 的多个实例共用同一目录，没有锁，后写覆盖先写。需要各存各的，就在文件名里带上 `widgetId`。

## 三、系统指标与内置监控挂件

**`window.VCPDesktop.metrics`**（`api/desktopMetrics.js`，主进程 `modules/ipc/desktopMetrics.js`）

- 九类快照：cpu、memory、disk、network、gpu、battery、docker、sensors、processes。
- `getSnapshot(options)`、`getCapabilities()`（30 秒缓存，状态取值 supported / permission_denied / provider_missing / error / unsupported），以及 `getCpuSnapshot` 等九个具名函数。
- 常用字段：`cpu.usagePct`、`memory.usagePct`、`memory.usedBytes`、`memory.totalBytes`；GPU 有 `memoryUsedMB`、`temperatureC`、`fanPercent`、`powerWatts`；Docker 用 `cpuPercent` / `memPercent`。Windows 上 `loadAverage` 为 null。
- 格式化：`formatBytes` / `formatRate` / `formatPercent` / `formatDuration`。

**`window.VCPDesktop.metricWidgets`**

- `list()` 返回 9 项，固定 ID 为 `builtin-monitor-{cpu|memory|disk|network|gpu|battery|docker|sensors|processes}`。
- `spawn(key, options)`：同 ID 已在桌面时返回 `reused: true`。
- `spawnMany(keys, { x, y })`：依次错开 24px。
- DesktopRemote 的 CreateWidget 传 `builtinWidgetKey` 即走这里。

## 四、styleAutomation（指标驱动全局样式）

`core/styleAutomation.js`。按 `intervalMs`（250ms–60s）拉指标快照，按规则写 CSS 变量或壁纸滤镜。只接受结构化规则，不执行任意 JS 或 CSS。

```json
{
  "enabled": true,
  "intervalMs": 2000,
  "rules": [
    { "id": "load", "sourcePath": "cpu.usagePct",
      "map": { "inMin": 0, "inMax": 100, "outMin": 0, "outMax": 1, "clamp": true, "round": 2 },
      "target": { "type": "cssVar", "name": "--desktop-cpu-load" } },
    { "id": "dim", "sourcePath": "cpu.usagePct",
      "map": { "inMin": 0, "inMax": 100, "outMin": 1, "outMax": 0.7, "clamp": true },
      "target": { "type": "wallpaper", "property": "brightness" } }
  ]
}
```

- `cssVar` 名称须以 `--desktop-` 开头，写在 `document.documentElement`。CSS 变量会穿透 Shadow DOM，每个挂件都能 `var()` 读到。
- `wallpaper` 支持 `blur` / `brightness` / `opacity`。
- 启动前记录基线，`stop()` 时恢复。`persist: true` 时配置写入 `globalSettings.styleAutomation`，开机读回。
- 渲染端接口：`setConfigPatch(patch, { persist })`、`getStatus()`。

## 五、performanceManager（按挂件计时）

- 默认关闭，零开销。`start()` 后沙箱登记过的回调按挂件累计毫秒，rAF 另计帧数。挂件顶层代码不计入。
- `getSnapshot()` 读取后清零，同一时间只宜有一个采样方。

## 六、持久化与推送

| 层 | 写入时机 | 位置 |
|---|---|---|
| 推送归档 | DESKTOP_PUSH 收到 finalize 且 HTML 非空 | `DesktopWidgets/{widgetId}/`，`origin: chat-stream`，`pinned: false` |
| 收藏 | 右键收藏 / CreateWidget `autoSave` | 挂件已有 `savedId` 时写回同一目录并加星（`pinned: true`）；没有时新建 `fav_*` |
| 布局预设 | 保存预设 | `DesktopData/layout.json`，只存 savedId 与坐标，按顺序恢复 |
| 待上屏队列 | 桌面关闭或隐藏时推送 | 内存队列，上限 5，先进先出；开窗时全部上屏 |

- 推送归档成功后，主进程向画布发 `{ action: 'archived', widgetId, savedId, name, dirUrl }`，挂件由此获得 `savedId`。右键收藏不再复制出第二份，widgetFS、右键刷新、编辑代码都可直接使用。
- 开机时画布已有随聊推送的挂件，就跳过默认预设，以免冲掉刚推来的内容。
- `replace` 推送只改第一个命中选择器的挂件；命中多个时控制台会列出其余挂件 ID。选择器宜带随机后缀保持唯一。
- 收藏与自动保存取挂件的原始源码。挂件脚本改写 `widgetData.contentBuffer` 只影响 ViewWidgetSource 的读回结果，不影响写盘。

## 七、挂件刷新与外部脚本

- 右键刷新与 Canvas 保存回推会先回收旧脚本登记的定时器、window 与 document 监听、Pixi 实例，再重新执行脚本。未经沙箱登记的资源（如裸用 `_realWindow.setInterval`）不在回收范围内，常驻任务仍宜自带单例令牌。
- `<script src>` 解析规则：
  - 相对路径（`app.js`、`./lib/a.js`）：挂件有归档目录时解析到该目录，否则按 `desktop.html` 所在目录解析。
  - `file:///` 绝对路径与同源脚本：fetch 源码后沙箱执行。
  - 跨域 CDN：原样加载。Pixi / Three / Anime 已预载时跳过。
  - 拿不到源码时跳过执行并在控制台报错，不再以非沙箱方式加载。
- 推送挂件的脚本在 finalize 时执行，此时 `archived` 回执尚未到达，所以首次运行时相对路径脚本仍按 `desktop.html` 解析。推送挂件宜写成单文件，或使用 `file:///` 绝对路径。

## 八、vcpAPI.post

```js
const r = await vcpAPI.post(
  [{ role: 'user', content: '用一句话介绍你自己' }],
  { model: 'gemini-2.5-flash', temperature: 0.4, max_tokens: 300 }
);
// r: { success, content, usage, raw } 或 { success: false, error }
```

- 未传 `model` 时使用 `AppData/settings.json` 的 `desktopWidgetModel`（可选字段，手动添加）。两者都没有时，服务器会报“未指定模型名称”，错误信息附带配置提示。
- 只支持非流式。`messages` 以第一个参数为准，`stream` 固定为 false。
- 请求经 VCP 服务器转发，服务器会注入系统内容，每次调用约 2300 输入 token 起步，与问题长短无关。模型类挂件以点击触发为主。窗口可见性冻结只暂停动画，定时器里的调用照常计费。

## 九、DesktopRemote 插件命令

对象与数组类参数（`configPatch`、`rules`、`metricsOptions`、`options`）可以直接传 JSON 字符串。

| 命令 | 参数 |
|---|---|
| `SetWallpaper` | `wallpaperSource`（URL、`file:///` 或 HTML 文本） |
| `QueryDesktop` | 无 |
| `QueryDock` | 无 |
| `ViewWidgetSource` | `widgetId` |
| `CreateWidget` | `htmlContent` / `builtinWidgetKey` / `metricComponent` 三选一；可选 `x` `y` `width` `height`（0 为合法值）、`widgetId`、`preSavedId`、`options`、`autoSave`、`saveName`、`scriptFiles` |
| `SetStyleAutomation` | 可选 `configPatch`（底稿）、`enabled`、`intervalMs`、`metricsOptions`、`rules`、`persist`；顶层字段覆盖底稿同名字段 |
| `GetStyleAutomationStatus` | 无 |

- CreateWidget 与 SetStyleAutomation 会在桌面关闭时自动打开窗口并等待 2 秒。
- CreateWidget 不经过 DESKTOP_PUSH，不产生推送归档；需要持久化就传 `autoSave` 或 `preSavedId`。

## 十、已知限制

- 挂件之间没有权限隔离，`_realDoc`、`_realWindow`、`window.VCPDesktop`、`window.desktopAPI` 对所有挂件可见。挂件级权限的设计方案见 README 三期 Widget API Provider。
- widgetFS 没有文件锁。
- `performanceManager.getSnapshot()` 读后清零。
- 主进程挂件存储通道会拒绝含路径分隔符、`.`、`..` 的挂件 ID。
