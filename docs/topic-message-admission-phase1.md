# 中央消息暂挂与 TopicSponsor 投递推进 · 一期施工基线

工程：p3e4d。源码区施工，不代表运行区部署或验收。

## 职责与默认语义

插件投信，中央模块决定入场与推进，现有聊天引擎生成回答。
默认 ReplyToTopic 只留言；REPLY_ADVANCE_ENABLED 缺省 false。
开启后只允许回复在入场后请求推进，CreateTopic 不随此开关触发。
CreateFlowlockTopic 保留既有语义，不额外建立私聊或 Flowlock Session。
REPLY_INVITE_PROMPT 用于单聊请求级邀请，不覆盖群聊自身邀请与选人规则。
投递接受时冻结策略，插件入队即返回，不等待目标生成，避免工具循环互锁。

## 中央调度契约

- 按 itemType + itemId + topicId 绑定；切换 UI 不改变归属。
- 请求准备、首字等待、流式/工具循环、非流式及最终保存均占用话题。
- 完整落盘后才能释放，视觉结束或函数返回不代表保存成功。
- 消息 FIFO；连续 Agent 留言可合并一次推进，人类消息构成生成硬边界。
- 群聊每位成员终稿保存后给暂挂消息入场机会，不等待整场结束。
- 活跃群聊复用原编排，禁止再启动并行循环；invite_only 不擅自选人。
- 等待与生成在中央串行提交锁外执行。
- 同话题单轮；活动 Agent 给自己当前话题留言不自唤醒。
- 本地自动连续轮次预算默认 8，人类参与重置；不是跨端因果预算。
- 暂挂日志持久化；重启恢复可见但暂停，用户明确继续后才推进。

## 消息与身份

保留 [xxx的发言]: 头。来源可选，只追加纯文本尾注：
[该发言发送自topic_xxx话题]
不添加 sourceConversation JSON。普通本地回答不自动回传来源；
目标 Agent 需要回信时自行调用 TopicSponsor。
发送者按注册身份解析，不把未知发送者伪装为主人。
附件与消息一同冻结；接受成功后才消费精确匹配的草稿。

## 暂挂 UI 与小 ×

输入框上方显示当前话题的发送者、摘要和状态。
小 × 只允许撤回尚未开始提交的项。
撤回与出队由同一串行权威裁决：
committed 或 commitStarted 的项不允许假报撤回成功。
failed/recovered 可显式继续；不得以撤回掩盖提交结果不确定。

## 独立租约持久化契约（已实现，故障边界继续审计）

目标：堵住获取独立租约后、故障诊断落盘前退出进程的窗口。
消息 FIFO 与租约账本分离，不通过伪造 queued 消息记录正常占用。

- 日志升级为 version 2：entries 与 standaloneLeases 在同一个临时文件中原子替换；读取兼容 version 1，未知版本与损坏结构拒绝。
- 中央服务维护独立租约记录；每次日志写入都保留完整账本，交接的暂写与恢复也不得丢失租约集合。
- 首次独立 acquire 必须先持久化 scope/token，再发布内存执行权和返回成功；同 token 重入不重复建账，其他 token 仍拒绝。
- acquireWhenIdle 的等待仍在串行锁外；持久化获取需要 await，返回包装对象，不能把等待 Promise 放进串行锁。
- 获取记录写入失败不得启动生成；若磁盘结果不明则保守暂停，不假报成功。
- release 先原子删除对应账本及批次，再删除内存租约、唤醒等待者。日志失败继续保留占用。
- transfer/transferToWaiting 同步更新持久 token；取消回滚恢复完整消息与租约快照。
- 重启不恢复执行权：独立租约转为可见的 uncertain 诊断，保留 scope/token，只能核对终稿，不能直接继续生成。
- 正常占用记录不参与消息提交、自动轮次与人类边界；诊断不进入聊天历史。
- 专测：获取落盘屏障、写入失败、同 token 重入、等待取消、交接回滚、释放失败、真实磁盘重启、精确终稿核验与其他话题隔离。

## 单聊工具返回暂挂中继（2026-11-10 调查完成，接入中）

莱恩明确：Agent 单聊工具调用与返回属于同一条超长流，不能把工具轮次误认为前端独立请求。
暂挂复用现有自动压缩的原生中继：工具返回边界 → 普通 Stop 渠道 → 流式收尾及 JSON 落盘 → 插入 → 话题推进。
不要求后端增加续接屏障，不另造流式协议；群聊仍在逐成员终稿边界入场，不增加此机制或上下文压缩。

已核实生产接线：
- mainChatStreamConsumer.consume 识别 END_ROLE_DIVIDE_USER 完整行，经 onToolReturnBoundary 发出边界回调。
- mainChatSurfaceAdapter 将其交给 chatManager.checkStreamContextBudget；后者通过 interruptCapability.interrupt 中止，失败走 bridge.cancelOperation 本地兜底。
- consumer.persist 先 projectTerminal 再 persistTerminal，保存成功才 afterPersist；保存失败不执行接续。
- afterPersist 当前先释放中央租约，再处理 Flowlock 等副作用，最后 finishStreamContextCompaction 压缩及接续。
- 中央 release 会立即 schedule/drain，因此不能直接把暂挂检测塞进现有检查函数后保持上述顺序，否则暂挂推进与压缩接续可能并发。

接入约束与施工顺序：
1. 工具返回检查同时查询绑定话题的可入场暂挂；只处理 Agent 主聊天，排除群聊、侧聊与恢复暂停/故障诊断项。
2. 一条旧流共享一次中止意图，压缩与暂挂不得重复中止；取消、撤回、切话题及迟到回调均按原 scope/messageId 裁决。
3. 原流保持租约直至已接收内容可靠保存；保存失败报告 uncertain、保占用，不插入不接续。
4. 如需压缩，在中央仍保有本话题执行归属期间完成压缩保存；暂挂与压缩共用中继收尾，不让各自发起一轮生成。
5. 中央串行处理旧轮结算、暂挂 FIFO 入场和续接归属；人类消息为硬边界，Agent 留言按冻结策略合并。
6. 默认只留言不得因“有暂挂”获得额外唤醒权限；旧流被中继暂停时的原任务接续与新消息请求推进必须明确区分。
7. Flowlock 不得在中继收尾期间抢先心跳；用户 Stop/取消不得被中继自动复活。
8. 专测：仅暂挂、仅压缩、同时发生、撤回、跨话题、重复边界、保存/中止/压缩失败、只留言与人类边界、Flowlock，以及群聊保持原行为。

接入进度：单聊工具返回暂挂中继已接中央 relay、主窗限定 IPC、preload、chatManager 边界检查与适配器 afterPersist。
