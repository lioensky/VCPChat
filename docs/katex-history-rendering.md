# 公式密集历史消息：分片与缓存施工记录

日期：2026-11-15

## 问题与范围

Markdown 模板缓存保存的是排版前的 HTML 与工具描述符，不能消除挂载后的公式编译和公式节点创建成本。本次不改变其原有 20MiB 预算，也不将消息运行态或事件绑定写回模板缓存。

公式编译仍在 UI 主线程进行，本次没有增加 Worker 公式编译。改动针对历史加载、规范正文替换与离屏内容恢复所共用的后处理入口；保留同步入口供原有调用方兼容。

## 实现

- 新增独立的 [公式处理器](../modules/renderer/mathRenderer.js)。
- [内容处理器](../modules/renderer/contentProcessor.js) 的引号、标签高亮与安全单美元规范化，均在元素边界剪枝，排除已排版公式整棵子树，不再逐文本节点向上查找公式祖先。
- 公式处理器也排除已排版公式、代码域和图表域；重复处理不进入公式内部。
- 公式定界符、花括号与转义字符的闭合规则与内置自动渲染器保持一致。相邻文本节点可以组成一个公式，不能跨元素配对。
- 安全单美元规范化保留原有价格保护；公式排版不额外注册宽松单美元定界符。
- 使用内置 KaTeX 的字符串排版能力，将缓存结果解析为新的节点，不缓存活动节点。
- 异步入口默认在约 6ms 时间预算或 16 个公式后，通过宏任务让出主线程。预算按处理器共享，不为每条消息单独配置一份预算。
- 时间预算是协作式预算，不是硬实时限制：单个复杂公式的编译不能中途抢占，浏览器样式、布局与绘制也可能超过预算。
- 每次恢复任务与写入前检查调用方的会话、内容版本及连接状态；正文替换或话题切换后，旧任务停止写入。
- 销毁处理器时清空缓存，取消并结算等待中的分片任务。

## 缓存边界

每个内容处理器独立持有一个最近最少使用缓存：

| 项目 | 上限或规则 |
| --- | --- |
| 字符串预算 | 12MiB |
| 条目数 | 1,000 |
| 单条大小 | 256KiB |
| 计费范围 | 缓存键及排版字符串，按 UTF-16 长度估算 |
| 身份 | 完整公式源码与行内／块级模式，不使用概率哈希 |
| 引擎更换 | KaTeX 实例对象变化时清空 |
| 宏状态 | 宏定义表达式及已有宏环境绕过缓存 |
| 生命周期 | 普通话题切换保留；重新初始化或销毁时清空 |

此预算不代表精确的 JavaScript 堆占用；容器和对象自身仍有开销。宏环境按一次正文处理创建，不跨消息共享。

只提供自动渲染函数、未提供字符串排版能力的自定义宿主，保留同步兼容降级；该降级不承诺公式级分片和结果缓存。

## 历史展示顺序

[消息渲染器](../modules/messageRenderer.js) 调整首批顺序：

1. 构建并挂载首批基础内容。
2. 请求滚动到最新内容并揭幕。
3. 跨过一个绘制机会。
4. 分片排版公式并完成其余后处理。
5. 运行原有最终滚动逻辑。

少量历史不再等待全部公式排完才揭幕。代价是用户可能短暂看到公式原文，随后逐步替换为排版结果；本次没有引入公式占位高度预测。

批次等待后处理任务完成，不再丢弃其异步结果。同一内容版本的首次重处理与可见性激活共用进行中的任务，避免两个公式写入者竞争。

## 验收

- [公式专项测试](../tests/math-renderer.test.mjs)：覆盖真实 KaTeX 语义与排版树对照、缓存身份、预算淘汰、宏隔离、单文本节点 760 个公式的分片撤销、销毁结算、代码域保护和子树剪枝。
- [历史集成测试](../tests/message-renderer-animation-island.test.mjs)：覆盖四条历史消息在公式编译前揭幕、切换后命中公式缓存、分片期间正文替换。
- 相关 12 个测试文件，共 150 项通过。
- [浏览器验收脚本](../scripts/test-math-render-browser.mjs)：使用真实 Edge 与内置 KaTeX，测试两段正文共 760 个合成公式。可通过环境变量指定其他浏览器可执行程序。

本机单次运行结果，浏览器版本 Edg/157.0.4341.60：

| 指标 | 冷加载 | 热加载 |
| --- | ---: | ---: |
| 排版及挂载总耗时 | 670ms | 536ms |
| 任务期间动画帧数 | 39 | 32 |
| 最大观测帧间隔 | 34ms | 17ms |
| 高亮耗时 | 1.2ms | 1.1ms |
| 公式缓存新增命中 | 0 | 760 |
| 最终元素数 | 34,576 | 34,576 |

缓存占用约 2.44MiB，无淘汰。以上是合成样本，不是报告中的两篇原始微分几何回复，不能与报告的 1.25 秒直接比较。

热缓存消除重复公式编译，但不会消除数万节点的解析、挂载、样式与布局成本。因此本次验收同时关注可交互性与缓存命中，而不宣称热加载瞬时完成。
