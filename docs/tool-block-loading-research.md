# 工具折叠块加载优化调研

## 结论与本次范围

“话题界面载入时不渲染折叠块正文”可行，工具密集、返回源码或大表格的话题最有希望明显受益。但无法仅凭源码保证整体载入速度大幅提升，也不能给出可信百分比。

本次第一项完成静态链路调研，不修改工具正文加载行为。第二项实现 ProjectForge 话题表面关闭磨砂及透明，并提供状态与浏览器级联回归测试。

必须区分两个概念：

- 延迟界面正文解析：历史原文保留、AI 请求不变，不节省 Token。
- 从 AI 上下文排除工具结果：会改变模型可见信息；已有隐藏按钮独立控制，不应与视觉折叠绑定。

## 当前成本

| 阶段 | 当前情况 | 延迟正文可节省什么 |
| --- | --- | --- |
| 历史读取、传输、反序列化 | 完整原文仍需加载 | 仅改渲染器不能节省 |
| 工具请求预处理 | 流水线先局部转义字段，后续展示使用原文再次转义 | 可减少大参数转义和字符串复制 |
| 工具调用折叠 | 正文已经转义并写入惰性模板，展开时克隆到活动 DOM | 已避开折叠态布局；进一步可省模板 HTML 解析与文本节点创建 |
| 工具结果折叠 | 已拆分全文、识别字段并独立解析 Markdown，生成正文 DOM | 可省正文 Markdown、DOM 创建与后处理，这是主要机会 |
| 超大结果 | 超过 50000 字符时只渲染前 80 行，其余原文存在 Map | 已有部分收益；超长单行仍可能保留几乎完整载荷 |
| 重型后处理 | 较旧消息按热区延期，但初始 HTML 已生成 | 延迟工具正文可以进一步避免折叠块扫描、高亮、图片处理等 |
| 历史分批 | 首批默认 5 条，后续默认 10 条，批次之间有等待 | 固定等待、空闲调度和头像等成本不因延迟工具正文消失 |

当前 HTML 缓存对工具结果及需要 HTML 作用域的消息绕过；含工具调用的普通文本可能命中缓存。因此冷加载与重复切换收益也会不同。

## 推荐实现方案

1. 在完整渲染流水线的早期提取工具块为不透明占位符，避免后续全文变换反复扫描载荷。
2. 初次仅生成标题、状态、隐藏按钮和必要的短摘要，不把正文塞进 HTML 属性或模板。
3. 由渲染器所属资源存储保留原文或原文区间。展开时才执行安全 Markdown、DOM 创建、图片处理和代码高亮。
4. 普通工具请求用纯文本节点显示参数；工具结果仍复用现有安全 Markdown 封印逻辑，不能直接注入原始 HTML。
5. 展开状态统一由展示层调用正文挂载能力，兼容旧式、紧凑、分组、单行合并和整轮折叠。
6. 重新渲染时保持相同源码块的身份和用户展开状态；不同消息不能共用运行时内容 ID。
7. 清空、编辑、切换话题和 Surface 销毁时清理资源；渲染会话和内容 revision 失效后不允许异步挂载。
8. 首版优先优化工具结果，不改日记或思维链等专用展示分支。

## 必须处理的影响

- 首次展开会把部分开销转移到点击时，超大内容需要分片或保留二级截断。
- 默认全部展开不会获得同等收益；失败和待确认结果的自动展开必须保持。
- 展示层当前读取正文生成命令摘要、路径、错误首行及 Diff 统计；应提供轻量元数据，而不是为了摘要再次渲染全文。
- 媒体结果自动展开与“图片 / 媒体结果”入口需要轻量媒体识别，不能以空正文 DOM 判断没有媒体。
- 浏览器页面查找、按 DOM 抽取的复制或导出看不到尚未挂载正文；需要改为从原始消息取值或显式挂载。
- TTS 当前剥离协议块，原则上不受影响；编辑、重发及 AI 上下文继续使用历史原文。
- 必须兼容嵌套结果、ESCAPE 字段、代码示例中的伪协议、未闭合流尾，不能用简单跨行正则替代扫描器。
- 原文仍在内存中，收益主要来自减少派生 HTML、DOM 与后处理，而不是完全消除原文内存。

## 建议测量

在真实 Electron 中分别测普通文本、长工具参数、大表格、源码结果、超长单行、媒体结果；区分冷加载、重复切换和首次展开。

记录历史读取时间、首屏可交互时间、完整历史插入时间、Markdown 耗时、后处理耗时、长任务、DOM 数量、堆内存和首次展开耗时。保持批次配置一致，覆盖所有展开策略及话题切换中途取消。

只有测量确认渲染占主要耗时，才能判断是否“大幅提高”；如果主要瓶颈是历史读取或批次固定延迟，渲染优化的整体收益有限。

## ProjectForge 话题表面行为

- 仅 assistant 的真实工具请求触发；普通提及、代码示例、工具返回数据不触发。
- 工具名字段可以出现在 valet、maid 或其他字段之后，工具名大小写不敏感；扫描时跳过其他字段完整载荷，避免参数示例误触发。字段闭合后，流式请求无需等待整个请求闭合即可生效。
- 批量历史开始前预扫描整个话题，包括尚未插入 DOM 的旧消息。
- 状态按聊天根隔离，编辑或删除最后一个调用后恢复；清空与销毁释放状态。
- 只覆盖消息外层、指定协议卡片及面板/沉浸共享底板，不修改任意正文 HTML、输入框和应用全局主题。
- 背景使用主题颜色的 RGB 分量并强制 alpha 为 1；因原主题靠透明混合壁纸，实色视觉会比原来更浓。
- 覆盖使用早期级联层的强制声明，以压过未分层主题中的强制模糊。
