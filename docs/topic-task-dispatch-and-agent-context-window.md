# 话题派工、查询与 Agent 上下文窗口整合

工程 pcc90；复用一期 p3e4d 的中央入场、单聊推进和 Flowlock 设施。本文件记录施工契约，不代表已实现或部署。

## 1. TopicSponsor：从当前话题派出子任务

- `ReplyToTopic` 不指定 `mode` 时继续按目的 `topic_id` 投递，现有单聊/群聊行为及推进策略不变。
- `mode: new_topic` 必须提供 `source_topic_id`、`target_agent`、`message` 与既有发送者字段；可选 `topic_name`。不接收目的 `topic_id`。发起者直接使用当前可见的话题 ID，单聊、群聊完全同契约；不预查接收方旧话题。来源用现有 resolver 校验，是回信地址，不是发送者认证。`maid` / `valet` 不参与目标路由。
- `target_agent` 接受精确 ID、大小写无关完整名或正向名称包含，例如 `小克` → `猫娘小克`。按上述优先级裁决，同层歧义给出候选，不建题。旧发送者解析不借此改变。
- 新话题属于接收方；不切换其当前话题，不复制来源历史。先校验并准备目标配置和历史目录，再通过中央入场写入唯一的首条任务、驱动首轮。明确派工不受普通已有话题回复的自动邀请开关影响；既有租约、停止和错误边界仍由中央入场裁决。
- 回执返回新 `topic_id`、目标身份与实际入场状态；受理不等于生成已开始或已完成。首条任务携带来源地址，接收方可按原有 `ReplyToTopic(topic_id=来源)` 主动回报，不自动回传任何普通回复。
- 同一稳定请求身份重试应回归同一话题和首条消息。现有进程内 TTL 缓存及仅扫描活动队列均不足以覆盖出队后重试。核对宿主请求 ID 来源与持久账本；验证建题后未入场、入场后回执丢失、队列已出队、冷重启。恢复不能覆盖历史、重新推进已完成任务或把显式撤回当失败重投。尚无法判定的状态显式报告，不另外建题。
- 心流是独立的显式请求；普通派工不能隐式进入心流或抢占接收方已有活动会话。复用现有待认领设施，区分请求登记、认领和会话开始；确认认领与首条任务入场的先后约束再接线。

## 2. TopicMemo：历史查询与手动话题锁退役

- 历史列表迁 `TopicMemo.ListTopics`，点读迁 `TopicMemo.GetTopicContent`。保留需用的消息状态检查及投递地址簿，不新增重复的历史读取接口。
- 退役旧解锁集合命令及所有声明、路由和提示词入口。不将旧批量读命令变成全历史正文扫描。
- 清理 Agent 手动锁的菜单、开锁标记、变体创建入口/快捷键、IPC 和业务分支。旧磁盘字段无需批量重写；核对移动同步兼容。运行中的 Flowlock session 保护不变。

## 3. 单聊「最近 N 楼」请求窗口

- 参考 GroupChat：默认不限；启用后最近 1–10000 条持久化历史消息，一条一楼。Agent 设置控制单聊，不覆盖群组已有策略。
- 在历史请求投影阶段截取，临时邀请、系统提示等不占历史配额。核对本轮输入已进入历史或作为独立参数的各入口，不能裁掉本轮输入或发送不完整的工具调用/结果。校验时间戳及内容哈希绑定按最终发出的消息计算。
- 核对手动发送、重新回复、插件推进、心流续跑及其他单聊请求路径。历史文件、界面显示、TopicMemo 回读不裁剪。

## 验收

1. 单聊和群聊分别发起，目标用简称，不提供任何接收方旧话题 ID；两条路径都可回原话题。歧义、无效来源、混合目的参数无写入。
2. 派工首条任务仅落一次，重试边界覆盖队列状态变化；当前选择保持不变，队列受理与生成状态不混报。
3. 普通派工不认领心流；显式派工按现有心流规则认领，不抢占已活动会话。
4. 旧手动话题锁入口下线，心流保护仍有效；模型请求只收到最近 N 楼，TopicMemo 仍能查回窗口外正文。
5. 记录自动化和实机验证分别覆盖的范围；未经授权不提交、不部署或重启。
