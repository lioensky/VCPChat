# VCP Music 歌词舞台四大核心视觉模式实现计划

## 1. 文档目标

本文确定 VCP Music 沉浸式歌词舞台未来的四个核心高级视觉模式，并给出可直接进入实施阶段的工程方案。

四个核心模式按产品展示优先级排列：

1. 凝彩（Tempera）
2. 商籁（Sonnet）
3. 镜台（Diorama）
4. 浮名（Fume）

这四个模式分别代表四种不可互相替代的歌词演出方向：

- 凝彩：实时动态图形歌词 MV。
- 商籁：高级动态图形设计与节目包装。
- 镜台：真实三维歌词空间与电影化运镜。
- 浮名：二维连续文字世界与长卷式镜头叙事。

现有流光、云阶、心象继续作为轻量模式和基础运行时验证模式，不从产品中移除。

## 2. 当前工程基础

VCP Music 已经具备以下基础能力：

- 独立歌词舞台宿主。
- 普通播放器与舞台模式切换。
- 统一播放时间与歌词帧快照。
- 逐词开始时间、结束时间和实时进度。
- bass、lowMid、mid、vocal、treble 与完整频谱数据。
- 统一主题色语义。
- 单活动模式实例。
- 模式创建、更新、暂停与销毁边界。
- 模式切换代际保护。
- 生命周期与控制器自动化测试。

当前舞台代码位于 `Musicmodules/music-stage`。

当前浮名实现是轻量原型，用于验证 Canvas 背景、文字英雄区、音频响应和模式销毁，不视为完整上游能力移植。

## 3. 总体技术路线

### 3.1 不引入 React 应用层

VCP Music 保持现有原生 JavaScript 页面结构，不为了视觉器引入完整 React 应用。

不使用 React 不代表放弃上游视觉实现所依赖的底层技术：

- DOM 模式继续使用原生 DOM、CSS 和现有统一帧循环。
- 商籁与凝彩使用原生 Pixi Runtime。
- 镜台使用原生 Three.js Runtime。
- 浮名使用 DOM、Canvas 2D 与 Pretext。
- Anime.js 可用于低频场景转场和离散动画。
- 高频逐帧状态统一由舞台帧时钟驱动。

### 3.2 React 能力替换表

| 上游能力 | VCP 原生替代 |
| --- | --- |
| React component mount | 模式实例 `mount` / 构造函数 |
| `useEffect` | 显式安装与 disposer 清理 |
| `useMemo` | 带上限的 Map 缓存 |
| `useRef` | 模式实例字段 |
| React state | 离散模式状态字段 |
| MotionValue | 舞台统一帧快照 |
| `useFrame` | 舞台 `updateFrame` |
| React Three Fiber Canvas | Three.js `WebGLRenderer` |
| React Pixi host | Pixi `Application` 或共享 Renderer |
| Suspense/lazy | 动态脚本加载与异步模式工厂 |
| effect cleanup | 模式 `destroy` |

### 3.3 产品优先级与施工顺序

产品展示优先级保持为：

1. 凝彩
2. 商籁
3. 镜台
4. 浮名

工程施工顺序建议为：

1. Pixi 公共底座。
2. 商籁。
3. 凝彩。
4. Three 公共底座。
5. 镜台。
6. 浮名完整体。

商籁先于凝彩施工，是因为两者共享 Pixi、纹理池、后处理和场景缓存能力，而商籁的程序编译与素材系统边界相对更容易切开。完成商籁后再实现凝彩，可以减少重复基础设施。

## 4. 共享高级渲染架构

### 4.1 重型模式协议

所有高级模式实现统一协议：

```js
{
    id,
    async mount(container, services, signal),
    activate(snapshot),
    updateFrame(snapshot),
    updateTrack(track, signal),
    updateLyrics(lines, signal),
    updateTheme(theme),
    resize(viewport),
    suspend(),
    resume(),
    async destroy()
}
```

### 4.2 重型模式服务

舞台宿主向模式提供以下服务：

```js
{
    clock,
    timeline,
    audioBands,
    theme,
    assetLoader,
    texturePool,
    fontMetrics,
    diagnostics,
    generation,
    isCurrentGeneration
}
```

模式禁止直接调用播放后端。播放、暂停、切歌、音量和进度仍由现有播放器负责。

### 4.3 渲染器所有权

首期采用“每个重型模式独占一个渲染器”的策略：

- 商籁拥有自己的 Pixi Application。
- 凝彩拥有自己的 Pixi Application。
- 镜台拥有自己的 Three WebGLRenderer。
- 浮名拥有自己的 Canvas 2D context。

模式退出时销毁其渲染器。

后续确认切换延迟和显存稳定后，可评估共享 Pixi Renderer，但不能在首期提前共享。独占渲染器更容易证明资源已经完全释放。

### 4.4 动态加载

高级模式不得随音乐窗口启动全部加载。

建议拆分为：

```text
Musicmodules/music-stage/
  engines/
    pixi-stage-runtime.js
    three-stage-runtime.js
    stage-texture-pool.js
    stage-render-target-pool.js
    stage-post-process.js
  modes/
    sonnet/
    tempera/
    diorama/
    fume/
```

用户第一次选择模式时再加载对应引擎和模式模块。

### 4.5 模式切换流程

1. 冻结旧模式最后一帧。
2. 将旧画面保存到静态过渡层或 RenderTexture。
3. 暂停旧模式。
4. 递增模式 generation。
5. 创建新模式。
6. 注入当前歌曲、歌词、时间、主题和频谱。
7. 等待新模式首帧就绪。
8. 交叉淡入新模式。
9. 销毁旧模式。
10. 释放静态过渡层。

切换期间禁止同时运行两个完整帧循环。允许旧模式保留静态纹理，但不允许继续计算。

## 5. Pixi 公共底座

商籁和凝彩共享以下基础能力：

- Pixi 动态加载。
- Application 创建与销毁。
- DPR 和最大像素预算。
- ResizeObserver。
- 场景 Container。
- RenderTexture。
- Texture 与 Bitmap 生命周期。
- 字体纹理。
- 后处理 Filter 链。
- 场景缓存与淘汰。
- 歌曲切换 staging。
- 暂停和恢复。
- Context lost 处理。
- 诊断计数。

### 5.1 像素预算

默认约束：

- DPR 最大值为 2。
- 默认最大像素量为 1920 × 1080 × 1.5。
- 高分屏按像素预算自动降低内部渲染分辨率。
- 后处理允许在 1x 或更低分辨率 RenderTexture 上执行。
- 用户界面与歌词时间不受内部渲染分辨率影响。

### 5.2 Pixi 销毁标准

销毁时必须释放：

- Application。
- Renderer。
- Ticker。
- Container 树。
- Graphics。
- Text/TextStyle。
- Sprite。
- RenderTexture。
- Filter。
- ImageBitmap。
- Blob URL。
- ResizeObserver。
- 异步图片请求。
- 场景缓存。
- 纹理池引用计数。

## 6. 核心模式一：凝彩 Tempera

### 6.1 产品定位

凝彩是歌词舞台的综合旗舰模式，目标是让每首歌曲自动生成一支实时动态图形歌词 MV。

### 6.2 必须保留的上游能力

- 歌词段落识别。
- shot 与 slice 编译。
- 短语分镜和整句分镜。
- 大面积主题色块。
- 网点、刻线与装饰。
- 圆滑构图族。
- 镂空构图族。
- 巨构族。
- 逐字入场。
- 字符落位时序。
- 歌词结束后的 release。
- 场景镜头运动。
- 场景间转场。
- 动态文字反色。
- 片尾卡。
- 画布图片池。
- 主题双色。
- 黑白灰模式。
- 封面渐变模式。
- 胶片颗粒。
- 对比度增强。
- RGB 色差。
- 透镜扭曲。
- 暗角。

### 6.3 VCP 适配重点

- 将上游 Line/Word 输入转换为 VCP 标准歌词行。
- 使用歌曲路径和歌词签名生成稳定 seed。
- 将 VCP 主题主色、强调色、辅助色和背景色映射到 Tempera palette。
- 将 VCP 封面路径解码为 Pixi Texture。
- 将图片池存储先限制为音乐模块本地配置。
- 使用现有舞台控制层，不移植上游控制 UI。
- 使用现有统一帧时钟，不建立永久独立 ticker。

### 6.4 分阶段交付

#### T1：程序与基础场景

- 移植段落、shot、slice 编译。
- 移植基础色块构图。
- 移植逐字排版。
- 支持主题双色。
- 支持播放、暂停和 seek 后绝对时间恢复。

#### T2：完整构图族

- 圆滑构图。
- 镂空构图。
- 巨构。
- 网点与刻线。
- 逐字入场样式。
- 镜头呼吸。

#### T3：后处理和转场

- 动态文字反色。
- 场景 wipe。
- RGB 色差。
- 透镜扭曲。
- 胶片颗粒。
- 暗角。
- RenderTexture 分辨率策略。

#### T4：素材与片尾

- 图片池。
- 图片前后景深度。
- 图片位置倾向。
- 片尾卡。
- 切歌 staging。
- 完整资源释放测试。

### 6.5 验收标准

- 同一歌曲、同一歌词和同一 seed 的构图稳定。
- seek 后画面直接恢复正确 shot。
- 暂停后所有时间驱动动画冻结。
- 切歌不显示上一首歌词。
- 连续切换 50 次无纹理累积。
- 4K 显示器不会突破像素预算。
- 无逐词歌词时仍能生成稳定分镜。

## 7. 核心模式二：商籁 Sonnet

### 7.1 产品定位

商籁是 VCP 最具技术品牌感的视觉模式，目标风格是高级动态图形、音乐节目包装、未来主义编辑排版和诗稿式切页。

### 7.2 必须保留的上游能力

- 段落与 shot 编译。
- 语义歌词分段。
- 字符级排版。
- 巨型镂空装饰文字。
- 外层框架。
- HUD、标尺和仪表。
- 动态短线与轨迹线。
- 固定几何浮标。
- 字符残影。
- 图标粒子。
- 摄像机聚焦。
- 多种 shot flow。
- 多题材动态图形库。
- 场景过渡。
- 片尾卡。
- 胶片颗粒。
- 对比度。
- RGB 色差。
- 透镜扭曲与色散。
- 半调网点。
- 暗角。

### 7.3 VCP 适配重点

- 首期只移植内建图形，不接上游 mod 系统。
- Lucide 图标通过 VCP 本地依赖解析为 SVG/Data URL。
- 使用 Pretext 或统一字体测量服务处理文本。
- 场景程序使用绝对播放时间，不依赖累计帧时间。
- 将主题强度映射为平静、标准、混乱三档。
- 音频响应只作用于装饰、后处理和有限镜头抖动，不破坏歌词可读性。

#### S3：镜头与转场

- 字符残影。
- 场景切换。

#### S4：后处理与资源池

- 透镜扭曲。

- 半调。
- 颗粒。
- 纹理池。
- 图标池。
- 片尾卡。

### 7.5 验收标准

- 长时间播放时动态图形不高频重复。
- 歌词始终处于安全可读区。
- 后处理关闭时能显著降低 GPU 负载。
- 图标 URL 和纹理引用计数最终归零。
- 切歌期间最多保留当前与 staged 两个场景。
- seek、循环和暂停不会造成镜头漂移。

## 8. 核心模式三：镜台 Diorama

### 8.1 产品定位

镜台是空间沉浸旗舰模式。歌词不再绘制在屏幕平面，而是成为三维世界中的实体，镜头沿歌曲路径穿行。

### 8.2 原生 Three 架构

建议建立 `DioramaRuntime`：

```js
class DioramaRuntime {
    async mount(host, services, signal) {}
    setSong(song, lines, signal) {}
    updateFrame(snapshot) {}
    updateTheme(theme) {}
    resize(viewport) {}
    suspend() {}
    resume() {}
    destroy() {}
}
```

内部拥有：

- Scene。
- PerspectiveCamera。
- WebGLRenderer。
- Fog。
- 歌词 Plane 组。
- 点云系统。
- 镜头控制器。
- Corridor sequencer。
- Raster texture cache。
- Geometry/material cache。
- Render target。

### 8.3 必须保留的上游能力

- 蜿蜒歌词路径。
- 每句歌词的空间姿态。
- 十种镜头语言。
- 当前歌词逐字 Plane。
- 邻近歌词纹理。
- 点云形态。
- 长廊形态。
- 背景尘埃。
- 音频脉冲。
- 雾场出生与消散。
- 普通辉光。
- 灵魂出窍。
- 渐变跟唱。
- 关键字颜色。
- 纯音乐虚拟长廊。
- 切歌空间飞行。
- 单曲循环返回飞行。

### 8.4 文字渲染策略

继续使用 Canvas Raster，不首选 SDF：

- 浏览器字体栈兼容性更好。
- 中文、日文、韩文和混合脚本更稳定。
- 当前行按字素或词分别生成纹理。
- 邻近行使用整句纹理。
- 纹理缓存严格限制在当前行前后窗口。
- 字体加载完成时递增 fonts epoch 并重建相关纹理。

### 8.5 分阶段交付

#### D1：基础三维歌词

- 原生 Three Scene。
- 路径和空间姿态。
- 当前行与邻近行。
- 基础 CameraRig。
- Fog。
- seek 与 resize。

#### D2：点云世界

- 背景尘埃。
- 点云表面。
- 点云长廊。
- 主题对比度适配。
- bass/mid/treble 响应。

#### D3：歌词跟唱效果

- 逐字亮起。
- 普通辉光。
- 灵魂出窍。
- 渐变跟唱。
- 关键字颜色。

#### D4：电影化交接

- 十种镜头语言。
- 纯音乐 Phantom corridor。
- 切歌双场景飞行。
- 单曲循环回程。
- 旧 segment 剪枝。

### 8.6 验收标准

- Renderer info 中 geometry、texture、program 数量有明确上限。
- 模式退出后主动调用 `renderer.dispose()`。
- 所有 Geometry、Material、Texture 和 RenderTarget 被释放。
- 切歌飞行期间允许双场景，结束后必须回落为单场景窗口。
- 镜头不直接响应音频，避免抖动影响阅读。
- Context lost 后可退出模式或安全重建。
- 连续播放一小时无 GPU 内存持续增长。

## 9. 核心模式四：浮名 Fume

### 9.1 产品定位

浮名是二维文字叙事旗舰模式。它强调歌词世界、满屏文章排版、镜头追焦和文字虚实，而不是依赖三维或重型后处理。

### 9.2 当前状态

现有 VCP 浮名原型已经实现：

- 当前句英雄区。
- 前后文。
- Canvas 几何背景。
- 频段响应。
- 轻量镜头移动。
- 模式级 Canvas 销毁。

完整体仍需重新引入：

- 全文世界布局。
- Pretext 段落排版。
- 世界坐标。
- 当前句追焦。
- stepped/smooth 镜头。
- 文字驻留。
- 邻近区域预热。
- 打印符号。
- 更完整的音频几何背景。
- 切歌世界交接。

### 9.3 推荐架构

浮名拆成四层：

1. `FumeArticleCompiler`：歌词到文章结构。
2. `FumeLayoutEngine`：Pretext 测量与世界布局。
3. `FumeCameraController`：镜头位置、速度和追焦。
4. `FumeBackgroundCanvas`：几何物体与音频响应。

DOM 只挂载镜头附近的有限文章块，不能把整首歌的所有逐字节点永久放入页面。

### 9.4 分阶段交付

#### F1：完整文章世界

- 全曲歌词编译。
- Pretext 布局。
- 世界坐标。
- 当前句与邻近块窗口化。
- 缓存键与缓存上限。

#### F2：镜头系统

- 平滑追焦。
- 定格追焦。
- 镜头速度。
- 文字停留比例。
- seek 跳转。
- 窗口缩放重排。

#### F3：排版演出

- 英雄标题比例。
- 打印符号。
- 前后文虚实。
- 当前词辉光。
- 副歌构图强化。
- 间奏空镜。

#### F4：背景与切歌

- 完整几何场景。
- 指针视差。
- 频段绑定。
- 旧世界冻结。
- 新世界预排版。
- 切歌镜头交接。

### 9.5 验收标准

- DOM 节点数量不随歌词总行数线性增长。
- 世界布局缓存具有固定上限。
- resize 使用 debounce 和 generation。
- 已销毁布局任务不得回写 DOM。
- 平滑模式无可见跳帧。
- 定格模式切换点与歌词时间一致。
- 普通 LRC 无逐词时间时有稳定降级。

## 10. 主题与封面色彩策略

所有核心模式遵循同一规则：

- 主题背景色决定大面积基底。
- 主题主文字色决定歌词静态颜色。
- 主题强调色决定正在演唱、高光和关键控制状态。
- 主题辅助色决定背景几何、未唱歌词和空间尘埃。
- 封面取色只提供环境色，不直接覆盖主题可读性规则。
- `text-on-accent` 决定强调色控件上的文字和图标。
- 关键词颜色只在演唱抵达该词时出现，不提前泄露。

主题变化必须平滑阻尼过渡，不能重建整个场景。只有字体、构图模式或纹理来源变化才允许重建。

## 11. 音频响应原则

- 镜头运动不得直接跟随原始频谱。
- 文字位置不得被高频频谱抖动破坏。
- bass 用于大尺度呼吸、点云脉冲和色块尺度。
- lowMid 用于世界位移和缓慢形变。
- mid 用于构图层级和局部强调。
- vocal 用于歌词辉光和当前字能量。
- treble 用于细粒子、线条、色散和高频装饰。
- 所有频段必须经过 attack/release envelope。
- 音频断线时动画保持时间驱动，只将音频响应平滑归零。

## 12. 内存与生命周期硬约束

任何核心模式合入前必须满足：

- 同一时刻只有一个活动模式实例。
- 最多允许一个 staged 新场景。
- 模式退出后 Canvas 数量回落。
- RAF/Ticker 数量不随切换增长。
- ResizeObserver 数量不随切换增长。
- 事件监听器数量不随切换增长。
- Texture、Geometry、Material 和 RenderTarget 有统计。
- Blob URL 全部 revoke。
- ImageBitmap 全部 close。
- 异步任务支持 AbortSignal 或 generation 检查。
- 缓存必须有容量上限和淘汰策略。
- 页面隐藏时重型模式 suspend。
- WebGL context lost 有明确降级路径。

## 13. 性能档位

每个高级模式提供三档统一质量：

### 节能

- DPR 1。
- 后处理关闭或低分辨率。
- 较低粒子量。
- 较短场景窗口。
- 限制到 30 FPS。

### 标准

- DPR 按像素预算动态决定。
- 主要后处理开启。
- 标准粒子量。
- 60 FPS 目标。

### 极致

- 更高纹理分辨率。
- 完整后处理。
- 更高粒子量。
- 仅在显卡能力满足时开放。
- 仍必须遵守最大像素和显存预算。

## 16. 完成定义

四大核心模式计划完成，需要同时满足：

- 凝彩达到实时动态图形歌词 MV 的完整体验。
- 商籁达到动态图形设计旗舰体验。
- 镜台达到稳定的三维歌词飞行体验。
- 浮名达到完整二维文字世界体验。
- 四模式均使用 VCP 播放、歌词、主题和频谱状态。
- 四模式均可独立加载和彻底销毁。
- 模式切换不重新加载歌曲。
- 模式切换不造成歌词时间漂移。
- 普通播放器与沉浸舞台不会同时运行重型视觉。
- 自动化测试可证明资源计数不会持续增长。
- Musicmodules 文档保留 Folia UI 移植声明。

## 17. 最终决策

VCP Music 歌词舞台未来不以增加大量轻量皮肤为核心，而以凝彩、商籁、镜台、浮名四种完整演出系统为核心。

其中：

- 凝彩负责综合视觉旗舰。
- 商籁负责品牌化动态图形旗舰。
- 镜台负责三维空间旗舰。
- 浮名负责二维文字叙事旗舰。

四者共享数据、时间、主题、音频和生命周期基础设施，但不得共享不可控的隐式状态。每个模式必须是可创建、可暂停、可恢复、可切歌、可销毁、可诊断的独立运行时。
